# Домашня робота

## Колекції та класи в C#

*List, Dictionary, Queue, Stack*

**Виконується в парах (2 особи)**

---

## Мета роботи

Закріпити навички створення залежних класів та роботи з колекціями C# (List, Dictionary, Queue, Stack) на більш комплексному завданні. Навчитися розподіляти роботу в парі та інтегрувати код.

## Вимоги до виконання

1. Створити класи згідно з описом завдання. Класи мають бути пов'язані між собою (один клас містить посилання або колекцію об'єктів іншого класу).
2. Використати **всі 4 колекції** (List, Dictionary, Queue, Stack) з обґрунтованим застосуванням кожної.
3. Використовувати **private set** для властивостей, які не повинні змінюватись ззовні. **Колекції мають бути private полями** — доступ до них тільки через методи класу.
4. **Вся логіка має бути в методах класів.** У Program.cs має бути лише створення об'єктів та виклик методів. Жодних foreach, while, Console.WriteLine з логікою у Program.cs!
5. Код має компілюватися та запускатися без помилок.

## Колекції та їх призначення

| Колекція | Призначення |
|---|---|
| List\<T\> | Зберігання основного списку об'єктів |
| Dictionary\<K,V\> | Швидкий доступ до об'єктів за ключем |
| Queue\<T\> | Моделювання черги (FIFO) |
| Stack\<T\> | Моделювання історії/логу (LIFO) |

## Варіант 1 (Група 1): Система управління рестораном

Створити систему управління рестораном, яка охоплює меню страв, замовлення від столиків, чергу замовлень на кухню та історію виконаних замовлень.

Самостійно продумайте назви класів, їх властивості, назви методів, типи колекцій та логіку взаємодії між об'єктами.

### Що має бути в системі

- Клас, що представляє страву (з ідентифікатором, назвою, ціною, категорією: закуска / основна / десерт / напій)
- Клас, що представляє замовлення від столика (з номером замовлення, номером столика, списком замовлених страв, статусом: нове / готується / виконано, загальною сумою що обчислюється)
- Головний клас-контейнер ресторану, що об'єднує всі колекції та методи для роботи з ними

### Які колекції використати (всі 4)

- List — для зберігання меню (всіх доступних страв)
- Dictionary — для обліку активних замовлень за номером столика (ключ — номер столика, значення — замовлення)
- Queue — для моделювання черги замовлень, що чекають приготування на кухні
- Stack — для ведення історії виконаних замовлень (останнє виконане — зверху)

### Обов'язковий функціонал (методи в класах, НЕ в Program.cs)

- Додати страву до меню
- Створити замовлення для столика з кількома стравами
- Зареєструвати замовлення в словнику за номером столика
- Відправити замовлення на кухню (поставити в чергу)
- Взяти наступне замовлення з черги на приготування
- Змінити статус замовлення (нове → готується → виконано)
- Завершити замовлення (перемістити до історії виконаних у Stack)
- Знайти замовлення за номером столика у словнику
- Вивести меню з фільтрацією за категорією
- Метод для виведення активних замовлень, обробки черги кухні, показу історії виконаних замовлень

**Program.cs:** лише створення об'єктів та виклик методів класів.

## Варіант 2 (Група 2): Система управління авіакомпанією

Створити систему управління авіакомпанією, яка охоплює рейси, пасажирів, чергу на посадку та історію завершених рейсів.

Самостійно продумайте назви класів, їх властивості, назви методів, типи колекцій та логіку взаємодії між об'єктами.

### Що має бути в системі

- Клас, що представляє рейс (з номером рейсу, містом призначення, датою/часом вильоту, максимальною кількістю місць, статусом: реєстрація / посадка / у польоті / завершений, списком зареєстрованих пасажирів)
- Клас, що представляє пасажира (з ідентифікатором, ім'ям, номером паспорта, класом обслуговування: економ / бізнес)
- Головний клас-контейнер авіакомпанії, що об'єднує всі колекції та методи для роботи з ними

### Які колекції використати (всі 4)

- List — для зберігання списку всіх рейсів
- Dictionary — для швидкого пошуку пасажира за номером паспорта
- Queue — для моделювання черги пасажирів на посадку (boarding)
- Stack — для ведення історії завершених (виконаних) рейсів

### Обов'язковий функціонал (методи в класах, НЕ в Program.cs)

- Додати рейс до списку
- Зареєструвати пасажира у словнику за номером паспорта
- Записати пасажира на рейс (з перевіркою наявності вільних місць)
- Поставити пасажира в чергу на посадку
- Посадити наступного пасажира з черги (витягти з Queue)
- Змінити статус рейсу (реєстрація → посадка → у польоті → завершений)
- Завершити рейс (перемістити до історії у Stack)
- Знайти пасажира за номером паспорта у словнику
- Вивести рейси з фільтрацією за статусом або містом призначення
- Метод для виведення всіх рейсів, обробки черги на посадку, показу історії завершених рейсів

**Program.cs:** лише створення об'єктів та виклик методів класів.

## Варіант 3 (Група 3): Система управління IT-проєктами

Створити систему управління IT-проєктами (спрощений таск-трекер), яка охоплює проєкти, задачі, чергу задач на виконання та історію завершених задач.

Самостійно продумайте назви класів, їх властивості, назви методів, типи колекцій та логіку взаємодії між об'єктами.

### Що має бути в системі

- Клас, що представляє розробника (з ідентифікатором, ім'ям, спеціалізацією: frontend / backend / QA)
- Клас, що представляє задачу (з ідентифікатором, назвою, пріоритетом: low / medium / high, статусом: todo / in progress / done, посиланням на призначеного розробника)
- Головний клас-контейнер проєкту, що об'єднує всі колекції та методи для роботи з ними

### Які колекції використати (всі 4)

- List — для зберігання всіх задач проєкту
- Dictionary — для обліку розробників за їх спеціалізацією (ключ — спеціалізація, значення — список розробників)
- Queue — для моделювання черги задач, що очікують на виконання (backlog)
- Stack — для ведення історії завершених задач

### Обов'язковий функціонал (методи в класах, НЕ в Program.cs)

- Додати розробника до словника за його спеціалізацією
- Створити задачу та додати її до загального списку
- Поставити задачу в чергу на виконання (backlog)
- Взяти наступну задачу з черги та призначити на розробника
- Змінити статус задачі (todo → in progress → done)
- Завершити задачу (додати запис в історію Stack)
- Змінити пріоритет задачі (low / medium / high)
- Вивести всіх розробників певної спеціалізації зі словника
- Вивести задачі з фільтрацією за статусом або пріоритетом
- Метод для виведення всіх задач, обробки черги backlog, показу історії завершених задач

**Program.cs:** лише створення об'єктів та виклик методів класів.

## Варіант 4 (Група 4): Система управління кінотеатром

Створити систему управління кінотеатром, яка охоплює фільми, сеанси, продаж квитків, чергу в касу та історію проданих квитків.

Самостійно продумайте назви класів, їх властивості, назви методів, типи колекцій та логіку взаємодії між об'єктами.

### Що має бути в системі

- Клас, що представляє фільм (з ідентифікатором, назвою, жанром, тривалістю у хвилинах)
- Клас, що представляє сеанс (з ідентифікатором, посиланням на фільм, часом початку, номером залу, кількістю доступних місць, ціною квитка, статусом: продаж квитків / йде показ / завершений)
- Клас, що представляє глядача/покупця (з ідентифікатором, ім'ям, списком придбаних квитків/сеансів)
- Головний клас-контейнер кінотеатру, що об'єднує всі колекції та методи для роботи з ними

### Які колекції використати (всі 4)

- List — для зберігання розкладу сеансів
- Dictionary — для швидкого пошуку фільму за його назвою (ключ — назва, значення — об'єкт фільму)
- Queue — для моделювання черги глядачів в касу
- Stack — для ведення історії продажу квитків

### Обов'язковий функціонал (методи в класах, НЕ в Program.cs)

- Додати фільм до словника
- Створити сеанс та додати його до розкладу
- Поставити глядача в чергу на касу
- Обслужити наступного глядача з черги — продати квиток на обраний сеанс (з перевіркою вільних місць)
- Змінити статус сеансу (продаж квитків → йде показ → завершений)
- Записати продаж квитка в історію (Stack)
- Знайти фільм за назвою у словнику
- Вивести розклад сеансів з фільтрацією за фільмом або за статусом
- Вивести список придбаних квитків конкретного глядача
- Метод для виведення повного розкладу, обробки черги в касу, показу історії продажів

**Program.cs:** лише створення об'єктів та виклик методів класів.

## Поради

- Розподіліть роботу в парі: наприклад, один створює допоміжні класи, інший — клас-контейнер. Потім інтегруйте код разом.
- Почніть зі створення класів із простими властивостями та конструктором.
- Потім додайте клас-контейнер з колекціями та методами.
- Наприкінці напишіть код демонстрації у Program.cs.
- Перевіряйте код на кожному етапі — компілюйте та запускайте після кожної зміни.
- Називайте класи, методи та змінні зрозуміло — назва має відображати суть того, що вона представляє.
